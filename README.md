# Albato Inspector MVP

Read-only Chrome extension для снятия структурированного снимка текущей страницы Albato. Текущая версия: **0.4.34**.

## Чтение журнала за выбранный период

В Журнале конкретной связки выберите период штатными средствами Albato и дождитесь загрузки записей. Затем нажмите **«Снять открытый журнал»**: расширение читает именно текущую вкладку, не открывая новую с периодом по умолчанию. Это отдельный JSON журнала, не объединённый с полным аудитом настроек. Период не устанавливается и не проверяется расширением; в результате указано `options.journal_period_source: current_open_tab` и `period_boundaries_verified: false`. Захватываются только загруженные записи текущей страницы (не более 60 запусков, не более 30 шагов на запуск); при пагинации следующие страницы надо читать отдельно. «Запустить полный аудит» по-прежнему открывает новую вкладку журнала с периодом по умолчанию.

## Чтение подробностей журнала

При включённом чтении журнала версия 0.4.34 обходит DOM-контейнеры запусков текущей страницы (до 60), раскрывает каждый по заголовку со стрелкой и проверяет классы `_expanded`/`rah-static--height-auto`. Для каждого видимого шага (до 30 на запуск) нажимает только его кнопку «Детали», ждёт нового устойчивого текста `.al-modal__content`, сверяет время запроса (если оно показано) и признаки содержимого с типом шага; неподтверждённое содержимое не экспортирует как данные шага. Закрывает окно через `.al-modal__header .al-modal__control.icon-close`. Данные сохраняются в `journal.evidence.journal_details`, пропуски — в `journal.evidence.journal_details_skipped`. `journal.summary.journal_details_complete` истинно только при подтверждённой привязке всех панелей без пропусков и усечения. Если окно не закрывается, обход останавливается. Статические проверки и регрессионный тест маскирования пройдены; живой полный обход после исправления ещё не подтверждён. Значения после `Токен запроса` маскируются и при наличии двоеточия, и без него. JSON всё ещё может включать персональные данные из журнала — перед отправкой его нужно проверять и скрывать вручную.

## Что умеет MVP

- считывает только текущую открытую страницу;
- определяет текущий экран: конструктор, журнал или аналитика;
- собирает заголовки, кнопки, ссылки, native- и custom-поля формы, выпадающие списки и видимые сообщения об ошибках;
- распознаёт видимые карточки шагов, приложения, операции, подключения и признак отключенного шага;
- извлекает видимые HTML-таблицы журнала и записи из текстовой разметки (дата/время, тип выполнения или шага, статус и доступное сообщение); `readable` требует записи либо явного сообщения о пустом журнале;
- извлекает индикаторы сохранения/несохраненных изменений, не считая их доказательством сохранения;
- исправляет ID связки из URL вида `/bundle/edit/387858`;
- маскирует пароли, токены, API-ключи, Bearer/JWT и значения чувствительных query-параметров;
- формирует JSON `albato-audit/v1`;
- копирует JSON в буфер обмена или скачивает его файлом;
- кнопка «Запустить полный аудит» автоматически обходит карточки шагов, собирает снимок каждого шага и открывает журнал во временной фоновой вкладке;
- иконка расширения использует отрисованный символ `T` из логотипа Albato: светло-серый фон, кораллово-оранжевый круг и белая геометрическая буква;
- в сканировании первого модуля отдельно считывает основную настройку, «Дополнительные настройки» подключения и «Фильтр»;
- при отладке модуля отдельно проверяет признаки тестирования, доступности operational data и сохранения настроек;
- после успешного снятия настроек выбранная панель Albato закрывается, а кнопка модуля превращается в «Скопировать JSON» до следующего «Прочитать сценарий»;
- переключатель «Запускать тест выбранного модуля» отдельно включает чтение образца/результата теста; по умолчанию выключен, поскольку тест может обратиться к внешнему сервису;
- переключатель «Проверять журнал запусков» позволяет полностью пропустить открытие журнала;
- объединяет результат в `albato-audit/v2` без отправки данных наружу;
- не изменяет настройки и не запускает тесты по умолчанию; тест отдельного модуля запускается только при включенном пользователем переключателе и может обратиться к внешнему сервису.

## Установка в Chrome

1. Откройте `chrome://extensions`.
2. Включите **Developer mode / Режим разработчика**.
3. Нажмите **Load unpacked / Загрузить распакованное расширение**.
4. Выберите эту папку `albato-inspector-mvp`.
5. Откройте нужную связку в Albato.
6. Нажмите значок расширения и выберите **Запустить полный аудит**.
7. Если включен переключатель **Проверять журнал запусков**, расширение дополнительно откроет журнал во временной вкладке. Chrome может закрыть popup при активации журнала; откройте расширение повторно, чтобы увидеть сохраненный результат. Если аудит еще идет, повторите через несколько секунд.
8. Нажмите **Скопировать JSON** и вставьте единый результат в чат с агентом.

## Безопасность

Расширение имеет доступ только к страницам `albato.com`, `*.albato.com`, `albato.ru` и `*.albato.ru`. Оно не отправляет данные в Hermes или сторонние сервисы, не выполняет записи в Albato и сохраняет последний снимок локально в `chrome.storage.local` только для текущего профиля Chrome.

Перед отправкой JSON агенту проверьте поле `evidence.visible_text`: если там остались лишние персональные данные, удалите их вручную.

## Ограничения MVP

- для открытия шага используется верхняя строка названия модуля (`GS 03 — ...`), а не область подключения `Connection to ...`;
- полный аудит отдельно различает открытие панели и подтверждение настроек операции: `opened_modules` не равно `configured_modules`;
- карточка подключения Google Sheets может открыться вместо настроек операции; это фиксируется как `connection_only_modules` и не считается полной проверкой шага;
- расширение блокирует кнопки сохранения, запуска, тестирования, сброса и удаления, но безопасность проверяется также по отчету `skipped`;
- журнал собирается во временной фоновой вкладке только если на текущем экране найдена ссылка `/bundle/history/<id>`;
- сетевые ответы Albato пока не анализируются отдельно;
- расширение не может доказать сохранение настройки по одному видимому значению;
- если модуль использует canvas или данные доступны только после внутреннего API-запроса, поле может остаться непроверенным;
- селекторы намеренно общие, поэтому точность зависит от фактической разметки страницы;
- расширение не управляет Albato и не может исправлять настройки.
